# 900E 反复出现 · 根因排查

> 现象：刷 ZUI boot 链 + 作者 system + 清 data 后，仍回 **900E**  
> 时间：2026-09-25

---

## 一、直接证据：镜像 MD5 对不上

| 分区 | 作者套件 | ZUI 线刷包 | 是否一致 |
|------|----------|------------|----------|
| boot | `4e5164d7…` | `ca6e201c…` | **否** |
| init_boot | `f8d1c530…` | `56dd77fa…` | **否** |
| vendor_boot | `c57a9d21…`（permissive） | `edc9f03c…` | **否** |
| vbmeta | **65536 B** `9ba41745…` | **8192 B** `76158477…` | **大小都不同** |
| system | 作者 `system_a_完全自包含` | （本次未用 ZUI system） | — |

**我们刷的是「ZUI 启动链 + 作者 system」混搭。**  
作者镜像是从**他那台已改机** dump 出来的，boot/init_boot/vendor_boot/vbmeta 必须**成套**，不能随便换 ZUI 那套。

---

## 二、还叠过这些（加重混乱）

| 操作 | 风险 |
|------|------|
| 刷过 **TWRP vbmeta**（64KB，关 AVB） | 与 ZUI 8KB / 作者 64KB 三套 vbmeta 混过 |
| HyperOS4 EROFS `Resizing system_a` 后末块失败 | **super 元数据可能已异常** |
| 多次 slot a flash / 未刷 dtbo | 边界问题 |
| `fastboot -w` | 只清 userdata/metadata，**修不好 boot/AVB/super** |

---

## 三、900E 在这里表示什么

- 不是普通 fastboot  
- 多半是 **早期启动校验失败 / 启动链崩溃** 后落到高通诊断口  
- 与「AVB/启动镜像不匹配」「super 超级分区异常」高度吻合  

---

## 四、结论（一句话）

> **不是作者 system 单独坏，而是「启动链」和「system/vbmeta」不是同一发布套件，外加 super 可能被 EROFS 试刷弄脏 → 无法通过启动校验 → 900E。**

---

## 五、修复方案（必须成套）

### 方案 A（推荐）：恢复「作者 HyperOS2 全套」

全部来自 `GSI_Kit\05_镜像\`，**同一来源**：

```bat
fastboot flash boot        boot_a_原始.img
fastboot flash init_boot   init_boot_a_原始.img
fastboot flash vendor_boot vendor_boot_a_原始_permissive.img
fastboot flash vbmeta      vbmeta_a_原始.img      :: 64KB
fastboot reboot fastboot
fastboot flash system      system_a_完全自包含.img
fastboot -w
fastboot reboot
```

> 若套件里还有 `vbmeta_a_patched.img`（文档有、本地缺文件），优先用作者 patched 版。

### 方案 B：恢复「ZUI 完全线刷」

用 QFIL/9008 或 fastboot 刷 **整包**（含 super_1..8），保证无混搭。

### 方案 C：实验包（HyperOS4）另说

EROFS 镜像末块 `Invalid argument`，**先不要当开机镜像**；修好 A/B 后再单独测。

---

## 六、操作注意

1. **同一套件成套刷**，不要 ZUI boot + 作者 system  
2. **vbmeta 大小** 要对（本机作者/TWRP 为 64KB；勿用 8KB 混入）  
3. 修好开机后再谈 TWRP（且 TWRP 自带 vbmeta 关 AVB，和作者 system 可再对齐）  
4. 若方案 A 仍 900E → **方案 B 整包线刷**（super 脏的唯一稳妥解）
