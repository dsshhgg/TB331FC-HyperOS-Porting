# 二次移植路线图（基于 TB331FC 套件经验）

目标：把「小米 HyperOS GSI」适配到**新的非小米设备**，或在 TB331FC 上继续改。

---

## 阶段 A · 素材与备份

1. 目标机 **完整分区备份**（至少 boot / init_boot / vendor_boot / dtbo / vbmeta / super）
2. 原厂固件 + EDL 救砖包（firehose elf）
3. 来源 GSI（本套件：`Hyperos-pipa-14-...MysticGSI` 或作者成品 `system_a_完全自包含.img`）
4. 工具：adb/fastboot、magiskboot、debugfs/erofs-utils、sqlite3、QFIL

---

## 阶段 B · 底座能起来

| 步骤 | 要点 |
|------|------|
| 解锁 BL | 本机 bootloader 无 `oem edl`，救砖只能硬件键进 9008 |
| 确认 SELinux | 建议 Enforcing；开关在 `vendor_boot` cmdline 等长替换 |
| 刷 GSI system | super 逻辑分区 → **fastbootd** |
| 首次启动 | 从原厂来可能需要 `fastboot -w` |
| root | KernelSU LKM 打在 `init_boot`；vermagic 可不一致（modversions） |
| **保留** ramdisk 内触控固件与密度 `build.prop` | 否则触控/显示异常 |

验收：能进桌面、adb 可用、`getenforce` 符合预期。

---

## 阶段 C · 功能修复优先级

按「用户感知」排序，照 TB331FC 模式做：

1. **开机自修复骨架**（`_boot_fix.sh` + second-stage rc）  
   - 永不 exit；seclabel `su:s0`；路径进 system_ext 不依赖 /data  
2. **崩溃类**（蓝牙软重启 → 杜比属性；开发者选项 → 3 条 avc）  
3. **硬件**（手写笔 support_pen 时序）  
4. **生态**（互传必须 priv-app；相机用 Aperture；蓝牙规格库补 deviceId）  
5. **特性表** `device_features/<device>.xml`（通信共享等 FeatureParser 链）  
6. **日志降噪**（magiskpolicy 合并一次调用；update_engine 噪声可忽略）  
7. **可选** NoBlur / 性能服务

每修一项：记「现象 → 日志/栈 → 根因 → 修法 → 验证命令」。

---

## 阶段 D · 打包发布

1. 改动全部塞进 system（`/system_ext/etc/tb331fc/` 等）  
2. `chcon`：尤其 `miuibooster_bin` → `miuibooster_exec`  
3. `sync` 后 `remount,ro`，再 dump：**`bs=4096`，禁止 `bs=1M count=N`**  
4. 校验字节数 = `blockdev --getsize64`  
5. 写 MD5SUMS + 部署 README + 踩坑记录  
6. 发布物最小集：成品 system img + 原始 init_boot + KSU 模块 + 可选补丁

---

## 与 TB331FC 的差异检查单（换机型时）

- [ ] `ro.product.device` 与 `device_features/*.xml` 文件名一致  
- [ ] 触控固件型号 / 输入配置（penfix idc/keylayout）  
- [ ] 音效：是否有杜比 / 是否误走 MiSound  
- [ ] 蓝牙云端库常用耳机 deviceId  
- [ ] 分区大小：system 是否塞得下 MIShare 等 priv-app  
- [ ] overlayfs 是否可用（TB331FC 不可用 → 只能 bind / dmctl）  
- [ ] dm 表布局（`dmctl replace` 参数因机而异）  
- [ ] SELinux：vendor 策略差异导致的 avc 集合
